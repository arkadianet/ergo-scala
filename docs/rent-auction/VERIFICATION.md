# Verification record

The machine-readable [verification.json](verification.json) is generated by
`python tools/rent-auction/verify.py --assemble --lithos PATH`.
It records the run date, selected commands, pass counts and assembled JAR SHA-256.
Full local logs are in `target/rent-auction-verification/`.

## Reproduction

Use JDK 11, the pinned node checkout, Python 3.10+, and the pinned patched Lithos
checkout described in [the adapter guide](../../tools/rent-auction/lithos/README.md).
Run the verifier from the node repository root. An unhandled test failure stops
verification and prevents a fresh success report from being written.

The machine-readable report is the authority if the package is subsequently rebuilt.
The entire repository test matrix, Docker integration suites and mainnet bootstrap
tests were not run. Expected-negative Scala cases emit validation errors in logs;
the suite outcomes determine success.

An initial combined regression run hit the existing wallet lock/unlock test's
key-count assertion (five keys instead of one), after an earlier successful run.
Serializing suites did not resolve that failure. Its `initWallet` call recreated
databases in the shared configured directory instead of the temporary stores
supplied by the fixture. That test now uses a separate temporary directory and
closes its recreated stores. Root suites also run sequentially. The final report
records the complete rerun; no wallet production logic was changed for this failure.

## Additional artifact checks

* The node assembles into a JAR including both compiled-script source resources
  and `org.ergoplatform.tools.RentAuctionCli`.
* The standalone JAR loads the real mainnet profile and emits the contract manifest.
* Its offline collection output equals the Scala-generated JSON plan exactly.
* The Python CLI launches the JAR and reads its JSON manifest successfully.
* The node patch and separate Lithos patch are checked for clean application to
  their pinned baselines. The source archive includes per-file SHA-256 checksums.
* New rent-auction Scala files are checked for accidental wildcard imports,
  excessive line lengths and trailing whitespace. `scalafmtCheck` is not a
  registered task in this baseline's build, so no scalafmt pass is claimed.

## What the tests establish

* The old fully consumed path can bypass ownership, while the proposed extra rules
  require deterministic token lots and separate producer payment.
* Distinct recreation/lot outputs prevent the demonstrated rent-aliasing case.
* Bids fund their value, preserve lot assets, and fully refund the prior bid.
* Deadline equality closes bidding; bounded extension and near-Int limits work.
* Invalid recipient encodings are rejected by the node's additional rule.
* Settlement transfers tokens and a deposit covering the entire winning bid.
* Native reserve execution accepts the new merge and increases reserve principal;
  the legacy current-reward sweep does not satisfy the new deposit covenant.
* No-bid closure removes the token-bearing auction state and burns its tokens.
* Connected collection/bid and settlement/merge transactions can share a block;
  bad order, double spends and missing commitments are rejected.
* Both persisted state modes enforce collection, roll back and reapply consistently.
* Normal mempool admission rejects claims; producer candidate selection validates
  them against the requested beneficiary and accounts for added cost.

## Limits

Fixtures use synthetic boxes and the repository's fake PoW scheme, not live funds.
Persistent state application is tested; complete networking/history/mainnet replay
is not. Existing history rules authenticate block sections, and this draft relies
on that existing path. HTTP tests use a local mock server for transport checks;
Scala tests supply the consensus evidence. Lithos testing uses the real client
source but not a live collateralized mining session.

No test count constitutes an independent contract audit, incentive analysis,
guaranteed auction participation or coordinated network activation. See
[REVIEW.md](REVIEW.md) for decisions still requiring external review.
